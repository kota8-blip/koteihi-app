# フロント開発サーバーとモックサーバーまとめ

## 📌 全体像

```
ブラウザ（http://localhost:3000）
    ↓ 画面を表示
【フロント開発サーバー】（npm run dev / ポート3000）
    ↓ APIリクエスト（/orders など）
【モックサーバー】（json-server / ポート3001）
    ↓ JSONデータを返す
mock/db.json
```

---

## 1. フロント開発サーバー（npm run dev）

### 役割
**Vue/Nuxtアプリを動かすためのサーバー**

### 具体的な機能
- HTMLやVueコンポーネントをブラウザで表示する
- ホットリロード（コード変更したら自動で画面更新）
- アセット（画像・CSS・JS）を配信
- **ポート：通常 3000番**（`http://localhost:3000`）

### 実行コマンド
```bash
npm run dev
```

### 例
- `pages/index.vue` を開くと、ブラウザで画面が表示される
- コードを編集すると、自動で反映される
- **画面の表示・操作に関わる部分**

---

## 2. モックサーバー（json-server）

### 役割
**バックエンドAPIの代わりにダミーデータを返すサーバー**

### 具体的な機能
- `mock/db.json` のデータを「API」として公開
- フロントが `/orders` などにアクセスすると、JSONデータを返す
- **ポート：3001番**（`http://localhost:3001`）

### 実行コマンド
```bash
npx json-server --watch mock/db.json --port 3001
```

### 例
- `http://localhost:3001/orders` にアクセスすると、`mock/db.json` の `orders` データが返ってくる
- フロントのコードで `axios.get('/orders')` を叩くと、このモックサーバーからデータを受け取る
- **データの取得・API連携に関わる部分**

---

## 3. なぜ2つ必要なのか？

### フロント開発サーバーだけではダメなのか？
→ **ダメ。APIからデータを取得できないから。**

### モックサーバーだけではダメなのか？
→ **ダメ。画面を表示できないから。**

### つまり
- **フロント開発サーバー**：画面を表示・動かす
- **モックサーバー**：APIのふりをしてデータを返す
- **両方必要！**

---

## 4. 実際の開発の流れ

### ステップ1：モックデータを準備
`mock/db.json` に受け取りたいデータを準備する

```json
{
  "orders": [
    { "id": 1, "name": "注文A", "price": 1000 },
    { "id": 2, "name": "注文B", "price": 2000 }
  ]
}
```

### ステップ2：2つのサーバーを起動

#### ターミナル1
```bash
npm run dev
```
→ フロント開発サーバーが起動（`http://localhost:3000`）

#### ターミナル2
```bash
npx json-server --watch mock/db.json --port 3001
```
→ モックサーバーが起動（`http://localhost:3001`）

### ステップ3：API関数を作成
`assets/services/order.js` を作成

```js
import request from '../utils/request';

export const orders = (params) => {
  return request({
    url: '/orders',
    method: 'GET',
    data: params,
  })
}
```

### ステップ4：コンポーネントでデータ取得
`components/orderList.vue` で使用

```vue
<script>
import { orders } from "~/assets/services/order";

export default {
  data() {
    return {
      orderListArr: []
    }
  },
  mounted() {
    this.initData();
  },
  methods: {
    async initData() {
      let res = await orders();
      if (res && Array.isArray(res)) {
        this.orderListArr = [...res];
      }
    }
  }
}
</script>
```

## 5. 本番環境との違い

### 開発環境（今回）
- **モックサーバー**（json-server）からダミーデータを取得
- `http://localhost:3001/orders` にアクセス

### 本番環境
- **実際のバックエンドAPI**から本物のデータを取得
- `https://api.example.com/orders` にアクセス

### どうやって切り替える？
**.env ファイル** や **nuxt.config.js の設定** で自動的に切り替わる  
→ **コードは書き換えない！**

例：
```bash
# .env.development（開発用）
API_BASE_URL=http://localhost:3001

# .env.production（本番用）
API_BASE_URL=https://api.example.com
```

## 6. 会社の環境では？

### 会社
**`npm run dev` 1回で「フロント開発サーバー + モックサーバー」が両方起動する**

- `package.json` の `scripts` に設定が組み込まれている
- または別のツール（webpack-dev-server、Vite など）が自動でモックを統合している

### 今回のプロジェクト
**手動で2つのコマンドを実行する必要がある**

- `npm run dev`（フロント）
- `npx json-server --watch mock/db.json --port 3001`（モック）

---

## 7. まとめ

| 項目 | フロント開発サーバー | モックサーバー |
|------|---------------------|---------------|
| **役割** | 画面を表示・動かす | APIのふりをしてデータを返す |
| **コマンド** | `npm run dev` | `npx json-server --watch mock/db.json --port 3001` |
| **ポート** | 3000番 | 3001番 |
| **対象ファイル** | `pages/`, `components/` など | `mock/db.json` |
| **本番での対応** | ビルド→デプロイ | 実際のバックエンドAPIに置き換わる |

### 重要ポイント
✅ **両方起動しないと開発できない**  
✅ **フロント側のコードは本番もモックも同じ**（URL切り替えだけ）  
✅ **モックを使えばバックエンドの完成を待たずに開発できる**  
✅ **会社では1コマンドで両方起動する設定になっている可能性が高い**

---

## 8. 次のステップ

1. `mock/db.json` に `orders` データを追加
2. `assets/services/order.js` を作成してAPI関数を定義
3. `components/orderList.vue` でデータ取得・表示
4. 2つのサーバーを起動して動作確認

これで「API連携 + モックデータ」の基本が身に付きます！
