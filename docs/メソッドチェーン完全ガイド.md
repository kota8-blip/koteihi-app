# ドット（.）記法完全ガイド

## ドット記法とは

`.`（ドット）で値やプロパティにアクセスする書き方。業務で見る長いコードの大半はこれ。

```js
オブジェクト.プロパティ.プロパティ.プロパティ...
```

---

## 業務でよく見る「長いドット記法」

### パターン1: 深くネストしたオブジェクトへのアクセス

```js
// よく見る長いコード
const userName = response.data.results.users[0].profile.personalInfo.displayName;

// これは以下のような構造を辿っている：
response = {
  data: {
    results: {
      users: [
        {
          profile: {
            personalInfo: {
              displayName: "田中太郎"
            }
          }
        }
      ]
    }
  }
}

// 読み方：
// response（レスポンス）の
// ↓
// data（データ）の
// ↓
// results（結果）の
// ↓
// users（ユーザー配列）の0番目の
// ↓
// profile（プロフィール）の
// ↓
// personalInfo（個人情報）の
// ↓
// displayName（表示名）
```

### パターン4: 配列アクセスとプロパティアクセスの混在

```js
// 配列の中のオブジェクトのプロパティに何度もアクセス
const result = data.companies[0].departments[2].employees[5].projects[0].tasks[3].status;

// 読み方：
// data.companies[0]           → 最初の会社
// .departments[2]             → 3番目の部署
// .employees[5]               → 6番目の従業員
// .projects[0]                → 最初のプロジェクト
// .tasks[3]                   → 4番目のタスク
// .status                     → ステータス
```

### パターン5: オプショナルチェーン（?.）を使った長いアクセス

```js
// 大規模システムで安全にアクセスするために使う
const value = apiResponse?.data?.results?.items?.[0]?.details?.specifications?.weight;

// ?. の意味：
// 左側がnullやundefinedの場合、エラーにならずundefinedを返す

// これがないと以下のようなエラーが出る：
// TypeError: Cannot read property 'results' of undefined
```

**?.がない場合のエラー例：**
```js
// apiResponseがnullだとエラー
const value = apiResponse.data.results.items[0].details.specifications.weight;
// ↑ TypeError: Cannot read property 'data' of null

// ?.があると安全
const value = apiResponse?.data?.results?.items?.[0]?.details?.specifications?.weight;
// ↑ undefinedが返るだけでエラーにならない
```

## 長いドット記法を読むコツ

### 1. 左から右に順番に辿る

```js
this.$store.state.cart.items[0].product.name
│    │      │     │    │      │       └─ 5. 商品名
│    │      │     │    │      └─ 4. 商品オブジェクト
│    │      │     │    └─ 3. 配列の0番目
│    │      │     └─ 2. カートのアイテム配列
│    │      └─ 1. カートのステート
│    └─ Vuexのストア
└─ Vueインスタンス
```

### 2. 各部分が何を返すかを意識する

```js
response.data.users[0].profile
│        │    │      │  └─ オブジェクト（プロフィール情報）
│        │    │      └─ オブジェクト（ユーザー1人分）
│        │    └─ 配列（ユーザーのリスト）
│        └─ オブジェクト（APIのデータ部分）
└─ オブジェクト（レスポンス全体）
```

### 3. どこで配列アクセスしているかをチェック

```js
data.items[0].subItems[2].value
     ^^^^^^          ^^^^^^
      配列              配列

// [0]や[2]は配列の何番目かを表す
// 配列じゃない部分は .プロパティ名 でアクセス
```

## メソッドチェーンとの違い

### ドット記法（値へのアクセス）

```js
// 値を取り出すだけ
response.data.users[0].name
// → "田中太郎" という値が返る
```

### メソッドチェーン（関数の連続実行）

```js
// 関数を連続で実行
array.filter().map().slice()
     ^^^^^^^^ ^^^^^ ^^^^^^^
     関数     関数   関数
```

## まとめ

1. **ドット記法は「オブジェクトや配列の中の値にアクセスする」書き方**
2. **左から右に順番に読む**
3. **業務の大規模システムでは階層が深くなりやすい**
4. **`?.`（オプショナルチェーン）でnull/undefinedエラーを防ぐ**
5. **配列アクセス`[0]`とプロパティアクセス`.name`が混在する**
6. **メソッドチェーン`()`とは別物：値へのアクセス vs 関数の実行**

## 具体例

### 1. 配列のメソッドチェーン

```js
[1, 2, 3, 4, 5]
  .filter(x => x > 2)    // [3, 4, 5] を返す
  .map(x => x * 2)       // [6, 8, 10] を返す
  .slice(0, 2)           // [6, 8] を返す
  .length                // 2（lengthプロパティ）

// 処理の流れ：
// [1, 2, 3, 4, 5]
// ↓ filter()
// [3, 4, 5]
// ↓ map()
// [6, 8, 10]
// ↓ slice()
// [6, 8]
// ↓ .length
// 2
```

### 2. 文字列のメソッドチェーン

```js
"  hello world  "
  .trim()              // "hello world" を返す
  .toUpperCase()       // "HELLO WORLD" を返す
  .split(" ")          // ["HELLO", "WORLD"] を返す
  .join("-")           // "HELLO-WORLD" を返す

// 結果: "HELLO-WORLD"
```

### 3. Promiseのメソッドチェーン

```js
fetchData()              // Promiseを返す
  .then(response => {    // Promiseのthenメソッド
    return response.data;
  })
  .then(data => {        // 次のthen
    console.log(data);
  })
  .catch(error => {      // Promiseのcatchメソッド
    console.error(error);
  });
```

### 4. Vuex（this.$store）のメソッドチェーン

```js
// dispatch は Promise を返す
this.$store.dispatch('user/login', credentials)
  .then(result => {
    console.log('ログイン成功');
  })
  .catch(error => {
    console.error('ログインエラー');
  });

// commit は undefined を返すので、チェーンできない
this.$store.commit('cart/addItem', item);  // これで終わり
```

## メソッドチェーンできるもの・できないもの

### ✅ チェーンできる（値を返す）

```js
// 配列メソッド
array.filter().map().slice()

// 文字列メソッド
string.trim().toUpperCase().split()

// Promise
promise.then().catch().finally()

// 配列から配列を返すメソッド
this.$store.state.cart.cartItems.filter().map()
```

### ❌ チェーンできない（undefinedを返す）

```js
// console.log
console.log("test").something  // ❌ undefinedを返すので無理

// Vuex の commit
this.$store.commit('mutation').something  // ❌ undefinedを返す

// forEach（undefinedを返す）
array.forEach().map()  // ❌ エラーになる
```

## 注意点

### 1. undefinedが返ると次が呼べない

```js
// ❌ ダメな例
array.forEach(x => console.log(x))  // undefinedを返す
  .map(x => x * 2);                 // ❌ エラー！

// ✅ 正しい例
array
  .map(x => {
    console.log(x);
    return x * 2;
  });
```

### 2. 長すぎるチェーンは読みづらい

```js
// ❌ 読みづらい
data.filter().map().reduce().slice().join().split().reverse().join();

// ✅ 適度に変数に入れる
const filtered = data.filter(x => x.active);
const mapped = filtered.map(x => x.name);
const result = mapped.join(", ");
```

### 3. エラーハンドリングを忘れない

```js
// ❌ エラーが起きたら止まる
fetchData()
  .then(data => processData(data))
  .then(result => saveResult(result));

// ✅ catchでエラーをキャッチ
fetchData()
  .then(data => processData(data))
  .then(result => saveResult(result))
  .catch(error => console.error('エラー:', error));
```

## 業務でよく見る「.の後に長いコード」パターン

### パターン1: .then() の中に長い処理

```js
this.$store.dispatch('user/fetchUserData', userId)
  .then(response => {
    // ← ここから長い処理が始まる
    console.log('ユーザー取得成功');
    const userData = response.data;
    
    if (userData.isActive) {
      this.userStatus = 'アクティブ';
      this.showWelcomeMessage();
    } else {
      this.userStatus = '非アクティブ';
      this.showWarningMessage();
    }
    
    this.userName = userData.name;
    this.userEmail = userData.email;
    
    return userData;
  })
  .then(userData => {
    // 次のthenでさらに処理
    return this.fetchUserOrders(userData.id);
  })
  .catch(error => {
    console.error('エラー:', error);
    this.showErrorToast();
  });
```

**解説:**
- `.then(コールバック関数)` のコールバック関数の中に複数行の処理
- `=>` の後の `{ }` 内に長いロジックを書く
- これが「.の後が長い」理由

---

### パターン2: .map() や .filter() の中に長い処理

```js
const processedData = rawData
  .filter(item => {
    // フィルター条件が複雑な場合
    const isValid = item.status === 'active';
    const hasPermission = item.permissions.includes('read');
    const isNotExpired = new Date(item.expiryDate) > new Date();
    
    return isValid && hasPermission && isNotExpired;
  })
  .map(item => {
    // map内で複雑な変換処理
    const discountRate = item.isPremium ? 0.8 : 1.0;
    const finalPrice = item.price * discountRate;
    
    return {
      id: item.id,
      name: item.name,
      originalPrice: item.price,
      finalPrice: finalPrice,
      discount: item.price - finalPrice,
      displayText: `${item.name} - ¥${finalPrice.toLocaleString()}`
    };
  })
  .sort((a, b) => b.finalPrice - a.finalPrice);
```

**解説:**
- `.filter()` や `.map()` の引数が複数行のアロー関数
- `{ }` ブロックで複雑な処理を書く
- これも「.の後が長く見える」典型例

### パターン4: async/await と .then() の混在

```js
async function loadUserData() {
  const userId = await getCurrentUserId();
  
  return fetchUserProfile(userId)
    .then(profile => {
      // 非同期処理の後にさらに処理
      if (profile.needsUpdate) {
        return updateUserProfile(profile.id, {
          lastLogin: new Date(),
          loginCount: profile.loginCount + 1
        });
      }
      return profile;
    })
    .then(updatedProfile => {
      this.userProfile = updatedProfile;
      this.isLoading = false;
      this.$myToast('success', 'プロフィール読み込み完了');
      return updatedProfile;
    })
    .catch(error => {
      this.isLoading = false;
      this.$myToast('error', '読み込みエラー');
      throw error;
    });
}
```

**解説:**
- Promise を返す関数の後に `.then()` が連続
- 各 `.then()` の中に複数行の処理
- これが業務で最もよく見るパターン

### パターン5: Vuexの処理チェーン

```js
this.$store.dispatch('cart/addItem', newItem)
  .then(() => {
    // カート追加成功後の処理
    this.$myToast('success', 'カートに追加しました');
    
    // 在庫を更新
    return this.$store.dispatch('inventory/decrementStock', {
      itemId: newItem.id,
      quantity: newItem.quantity
    });
  })
  .then(() => {
    // 在庫更新成功後の処理
    console.log('在庫更新完了');
    
    // カート合計を再計算
    return this.$store.dispatch('cart/calculateTotal');
  })
  .then(total => {
    // 合計金額を表示
    this.totalAmount = total;
    this.showCheckoutButton = true;
  })
  .catch(error => {
    // エラー時の処理
    this.$myToast('error', '処理に失敗しました');
    console.error('エラー詳細:', error);
    
    // ロールバック処理
    this.$store.dispatch('cart/rollback');
  });
```

**解説:**
- 複数の dispatch が `.then()` でチェーン
- 各ステップで別の処理を実行
- エラーハンドリングも含めて長くなる

## 「.の後が長い」コードを読むコツ

### 1. まず全体の流れを把握する

```js
データ取得()
  .then(データ加工)
  .then(保存)
  .catch(エラー処理)
```

最初は細かい中身を読まず、「何をしているか」の流れだけ追う。

### 2. 各ブロックを個別に理解する

```js
.then(response => {
  // ↓ このブロックだけに集中
  console.log('成功');
  return response.data;
})
```

一つずつのブロックに分けて理解する。

### 3. コールバック関数の引数と返り値を確認

```js
.then(response => {       // ← 引数: response
  const data = response.data;
  return data;            // ← 返り値: data（次のthenに渡される）
})
.then(data => {           // ← さっきの返り値がここに入る
  console.log(data);
})
```

---

## まとめ

1. **メソッドチェーンは「返り値に対して次の処理をする」仕組み**
2. **何を返すかで次に使えるメソッドが決まる**
3. **配列・文字列・Promiseでよく使う**
4. **undefinedを返す関数ではチェーンできない**
5. **業務でよく見る「長いコード」は .then() や .map() の中に複数行の処理が書かれている**
6. **全体の流れ → 各ブロック → 引数と返り値 の順で読むと理解しやすい**
