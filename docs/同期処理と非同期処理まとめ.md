# 同期処理と非同期処理まとめ

## 📌 分かりやすい言い換え

### 同期処理 = **順番通り処理**
- 1つずつ順番に実行される
- 前の処理が終わるまで次に進まない

### 非同期処理 = **バラバラ処理（並行処理）**
- 完了を待たずに次に進む
- 複数の処理を並行して実行できる

---

## 💡 用語の由来（参考）

### 同期（どうき / Synchronous）
- 「同期」= 同じ時期、タイミングが揃っている
- **※分かりにくい用語なので「順番通り処理」と覚える方が良い**

### 非同期（ひどうき / Asynchronous）
- 「非」= 否定、つまり「同期ではない」
- **※分かりにくい用語なので「バラバラ処理」と覚える方が良い**

---

## 🔥 同期処理（順番通り処理）とは？

### 特徴
- **1つずつ順番に処理される**
- **前の処理が終わるまで次に進まない**
- **他の処理がブロックされる（止まる）**

**= 要するに「順番待ち」**

### 例
```javascript
console.log('1');
console.log('2');
console.log('3');
```

**実行結果：**
```
1
2
3
```

→ **順番通りに実行される**

---

### 問題点

```javascript
console.log('開始');
// 5秒かかる処理（同期）
for (let i = 0; i < 5000000000; i++) {}
console.log('終了');
console.log('次の処理');
```

**実行結果：**
```
開始
（5秒待つ）
終了
次の処理
```

→ **重い処理が終わるまで、画面が固まる（操作できない）**

---

## ⚡ 非同期処理（バラバラ処理・並行処理）とは？

### 特徴
- **処理の完了を待たずに次に進む**
- **他の処理をブロックしない（止まらない）**
- **完了したら後で結果を受け取る**

**= 要するに「並行作業」**

### 例
```javascript
console.log('1');
setTimeout(() => {
  console.log('2');
}, 1000);
console.log('3');
```

**実行結果：**
```
1
3
（1秒後）
2
```

→ **`setTimeout`の完了を待たずに次の処理が実行される**

---

### メリット

```javascript
console.log('開始');
// 5秒かかる処理（非同期）
setTimeout(() => {
  console.log('完了');
}, 5000);
console.log('次の処理');
```

**実行結果：**
```
開始
次の処理
（5秒後）
完了
```

→ **重い処理をバックグラウンドで実行し、画面は操作可能なまま**

---

## 🔍 非同期処理の代表例

### 1. **API通信**
```javascript
fetch('https://api.example.com/data')
  .then(response => response.json())
  .then(data => console.log(data));
```

### 2. **タイマー**
```javascript
setTimeout(() => {
  console.log('3秒後に実行');
}, 3000);
```

### 3. **ファイル読み込み**
```javascript
fs.readFile('file.txt', (err, data) => {
  console.log(data);
});
```

## 📖 `async/await`とは？

### 特徴
- **非同期処理を同期処理っぽく書ける**
- **コードが読みやすくなる**
- **エラーハンドリングが簡単**

---

### `await`なし（本当の非同期）

```javascript
async function initData() {
  let res = past(this.userInfo.user_id); // 待たずに次へ
  console.log('すぐ実行される');
  console.log(res); // まだ完了していないのでPromise
}
```

**実行結果：**
```
すぐ実行される
Promise { <pending> }
```

→ **完了を待たない**

---

### `await`あり（完了を待つ）

```javascript
async function initData() {
  let res = await past(this.userInfo.user_id); // 完了まで待つ
  console.log('完了後に実行される');
  console.log(res); // データが取得できている
}
```

**実行結果：**
```
完了後に実行される
{ data: [...] }
```

→ **完了を待ってから次に進む**

---

## 💡 重要なポイント

### `await`を使っても「非同期処理」と呼ぶ理由

**`await`は「その関数の中では待つ」が、「他の処理はブロックしない」から**

---

### 具体例

```javascript
console.log('1');

async function fetchData() {
  console.log('2');
  let res = await past(); // ここで待つ
  console.log('4');
}

fetchData();
console.log('3');
```

**実行結果：**
```
1
2
3
（完了後）
4
```

---

### なぜこうなるのか？

- `await`は**その関数の中では順番通り**に進む
- でも**他の処理（`console.log('3')`）は止まらない**
- これが「非同期」の本質

---

## ✅ 同期処理（順番通り） vs 非同期処理（バラバラ）

| 項目 | 同期処理（順番通り） | 非同期処理（バラバラ） |
|------|---------|-----------|
| **進み方** | 順番通り | タイミングがバラバラ |
| **待つか** | 完了まで待つ | 完了を待たない |
| **他の処理** | ブロックされる（止まる） | ブロックされない（止まらない） |
| **画面** | 固まる可能性がある | 操作可能なまま |
| **例** | `console.log`, `for`ループ | `setTimeout`, `fetch`, `async/await` |

---

## 🚀 実務での使い分け

### 同期処理を使う場面
- 簡単な計算
- データの変換
- 順番通りに実行したい処理

### 非同期処理を使う場面
- **API通信**
- **ファイル読み込み**
- **タイマー**
- **重い処理**（画面を固めたくない）

---

## ⚠️ よくある誤解

### ❌ 誤解1：「`await`を使うと同期処理になる」
→ **正解：`await`を使っても非同期処理です。他の処理はブロックされません。**

### ❌ 誤解2：「非同期処理中は画面が操作できない」
→ **正解：非同期処理中でも画面は操作可能です。ただし、データが取得できるまで表示されないだけです。**

### ❌ 誤解3：「非同期処理は順番がバラバラになる」
→ **正解：`await`を使えば、その関数の中では順番通りに進みます。**

---

## 📊 まとめ

### 同期処理
- ✅ 順番通りに実行される
- ❌ 重い処理があると画面が固まる

### 非同期処理
- ✅ 他の処理をブロックしない
- ✅ 画面が固まらない
- ❌ タイミングがバラバラになる（`await`で制御可能）

### `async/await`
- ✅ 非同期処理を同期処理っぽく書ける
- ✅ コードが読みやすい
- ✅ エラーハンドリングが簡単

---

**実務では、API通信やファイル読み込みなど、時間がかかる処理は必ず非同期処理を使います！**
